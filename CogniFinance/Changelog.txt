[Unreleased] - 2024-05-XX (v1.95)
🚨 BREAKING CHANGES & ARCHITECTURAL UPGRADES
Transitioned to DEK/KEK Envelope Encryption: Moved away from direct passphrase-based SQLCipher encryption to a modern Data Encryption Key (DEK) / Key Encryption Key (KEK) envelope architecture. The database is now encrypted with a random 256-bit DEK, which is wrapped by KEKs derived from user passphrases.
Transitioned to Append-Only Immutable Ledger: Replaced standard UPDATE and DELETE SQL operations with an append-only accounting model. Transactions are now "voided" via reversing entries rather than deleted, and "edited" by voiding the original and creating a new one.
🔒 Security & Cryptography
Added crypto_envelope.py: New module handling DEK generation, PBKDF2-HMAC-SHA256 KEK derivation (600,000 iterations), and AES-256-GCM wrapping/unwrapping.
Instant Passphrase Rotation: Because the database is encrypted with the DEK, changing the primary passphrase no longer requires re-encrypting the entire database. It now takes milliseconds by simply re-wrapping the DEK in the metadata envelope.
Native Multi-Key Recovery: The recovery passphrase now derives its own KEK to unwrap the exact same DEK. This natively supports multiple unlock methods without needing the legacy Fernet-based .recovery_escrow.json workaround.
Seamless Legacy Migration: Added an automated migration routine in main.py (Scenario C) that detects older passphrase-direct databases, securely exports them to a new DEK-encrypted file, and generates the envelope on the user's next launch.
📊 Ledger & Accounting Core
Implemented void_transaction(): Replaces delete_transaction(). Creates a perfect mathematical reversal (flipping DR/CR) and marks the original transaction with is_voided = 1.
Implemented edit_transaction(): Replaces update_transaction(). Voids the original transaction and posts a brand new one with the updated details, preserving the immutable historical record.
Added Voiding Columns: Added is_voided, reversed_by_tx_id, and reverses_tx_id to sql_transactions to track the lifecycle of reversed entries.
Filtered Voided Data: Updated _load_from_db() and _imported_id_exists() to strictly ignore is_voided = 1 transactions, ensuring the UI and import engines only see active ledger state.
🛡️ Forensic Audit Trail & Integrity
Cryptographic Hash Chaining: Added prev_hash and row_hash columns to sql_transaction_history. Every audit log entry now includes a SHA-256 hash of its contents combined with the previous row's hash, creating an unbroken, tamper-evident chain.
Added verify_audit_chain_integrity(): New method in GeneralLedger that reads the history table in chronological order and recomputes the hash chain to detect any raw SQL tampering or external database manipulation.
Quarterly Deep Audit Integration: Integrated the hash chain verification into the DeepIntegrityChecker. The quarterly background pytest suite now automatically verifies the audit trail's cryptographic integrity using the live DEK passed via environment variables.
🛠️ Internal Plumbing & Refactoring
Updated Core Signatures: GeneralLedger, AuditLogReader, TestRunnerManager, and DeepIntegrityChecker now accept and pass dek_hex instead of passphrase.
Updated SQLCipher PRAGMA: Connections now use PRAGMA key = "x'{dek_hex}'" to pass the raw hex DEK directly to SQLCipher.
Fixed Backup Encryption: Updated create_encrypted_backup() to attach the backup database using the raw hex DEK instead of the legacy passphrase string.
