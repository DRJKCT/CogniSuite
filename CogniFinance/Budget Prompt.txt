Engineering Brief: Hybrid Budget Engine
Mission
Replace the current simple CRUD budget tab with a Zero-Based Budgeting (ZBB) + Envelope Tracking system that coexists with CogniFinance's existing append-only double-entry ledger. The budget engine is a planning layer that reads from the ledger but never writes to it. Every design decision below flows from that single constraint.

Non-Negotiable Rules
R1 — Ledger isolation. sql_transactions, sql_transaction_lines, and sql_transaction_history are read-only from the budget engine. Budget operations must never call record_transaction, edit_transaction, or void_transaction. Budget activity must never appear in sql_transaction_history or affect verify_audit_chain_integrity().

R2 — Categories are not accounts. A category is a budget envelope ("Groceries"). An account is a chart-of-accounts entry ("Checking Account"). The existing sql_budgets.category column stores account names — that legacy conflation is what this overhaul removes. Do not propagate it.

R3 — Money is Decimal, stored as TEXT. Never REAL, never FLOAT. Every monetary column stores the result of str(Decimal). Every read goes through money() from ledger.py. Never use SQL SUM() on a money column — SQLite coerces TEXT to REAL and destroys precision. Sum in Python:

python
# Correct
cur.execute("SELECT amount FROM sql_budget_ledger WHERE category_name = ?", (cat,))
total = sum((money(r[0]) for r in cur.fetchall()), ZERO)

# Wrong — silent precision loss
cur.execute("SELECT SUM(amount) FROM sql_budget_ledger WHERE category_name = ?", (cat,))
R4 — Booleans are INTEGER 0/1. Match the existing schema (reconciled, case_sensitive, enabled).

R5 — Timestamps are written from Python, as datetime.now().isoformat(timespec="seconds"). Do not use DEFAULT CURRENT_TIMESTAMP.

Codebase Conventions to Match
The user has uploaded ledger.py, budgets_tab.py, ui_helpers.py, and ui_main.py. Extend the real code — do not invent method signatures. Relevant existing pieces you must be aware of:

money(value) — the canonical Decimal quantizer, in ledger.py

ZERO — the canonical Decimal("0.00"), in ledger.py

Account.NORMAL_BALANCES — maps account type → "DR"/"CR"

update_account(old, new, type) — cascades renames across ledger tables; you must extend it (see §6)

ui_helpers.ACCOUNT_COLORS — maps account type → hex color; reuse it, do not duplicate the palette

_init_db() in ledger.py — where new tables are created

_load_from_db() in ledger.py — where in-memory caches are built

If a method you need doesn't exist, add it to ledger.py. Do not assume one exists.

1. Schema
Add these tables inside _init_db():

sql
CREATE TABLE IF NOT EXISTS sql_budget_envelopes (
    category_name   TEXT PRIMARY KEY,
    linked_account  TEXT,
    rollover_policy TEXT NOT NULL DEFAULT 'positive_only',
    is_active       INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE IF NOT EXISTS sql_budget_income_plan (
    month           TEXT PRIMARY KEY,
    expected_amount TEXT NOT NULL,
    income_source   TEXT NOT NULL DEFAULT 'last_month',
    derived_amount  TEXT,
    created_at      TEXT NOT NULL,
    updated_at      TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS sql_budget_ledger (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    month         TEXT NOT NULL,
    category_name TEXT NOT NULL,
    event_type    TEXT NOT NULL,
    amount        TEXT NOT NULL,
    related_id    INTEGER,
    note          TEXT,
    created_at    TEXT NOT NULL
);
Column semantics:

sql_budget_envelopes.linked_account — nullable. May reference sql_accounts.name by convention but carries no foreign key. Envelope names are user-facing labels and are never cascaded on account rename; linked_account is.

sql_budget_envelopes.rollover_policy — 'none' | 'positive_only' | 'full'.

sql_budget_income_plan.income_source — 'last_month' | 'avg_3mo' | 'avg_6mo' | 'manual'.

sql_budget_income_plan.derived_amount — NULL when income_source = 'manual'; otherwise the auto-derived base the user may have overridden.

sql_budget_ledger.event_type — 'assign' | 'unassign' | 'move_in' | 'move_out' | 'rollover'.

sql_budget_ledger.amount — always positive. Sign is implied by event_type. This is deliberate; see §3.

sql_budget_ledger.related_id — groups the two rows of a single move. NULL for standalone assign/unassign/rollover rows.

2. Migration from sql_budgets
On first startup after this change, before any UI touches the new tables:

If sql_budgets exists and has rows, for each distinct category value insert one row into sql_budget_envelopes with linked_account = category, rollover_policy = 'positive_only', is_active = 1.

For each sql_budgets row, insert one 'assign' row into sql_budget_ledger with the same month, category, and amount.

Rename sql_budgets to sql_budgets_deprecated. Do not drop it. Do not write to it again.

get_all_budgets() must remain callable for backward compatibility. Reimplement it to build the synthetic list from sql_budget_ledger grouped by (category_name, month). Mark the method # DEPRECATED in a docstring; do not remove it.

3. Why event_type and Positive-Only amount
A single user action ("move $50 from Buffer to Dining") produces two rows sharing a related_id:

id	category_name	event_type	amount	related_id
41	Buffer	move_out	50.00	77
42	Dining	move_in	50.00	77
If amount carried the sign instead, any aggregate would need to know which rows to include to avoid double-counting. With positive-only amounts and explicit event_type, the semantics of each aggregate are unambiguous and stated once, here:

Ready to Assign = SUM(assign) − SUM(unassign) for the month. Move events are excluded entirely — they neither add nor remove money from Ready to Assign, only redistribute it.

Assigned to a category (this month) = SUM(assign) + SUM(move_in) − SUM(move_out) − SUM(unassign) for that category, filtered by month.

Cumulative available for a category = the same sum, unfiltered by month, from inception through the target month.

Do not collapse these into a shared helper. They are three different aggregates and merging them is how the original spec's double-counting bug arises.

4. Interface Contract (ledger.py Additions)
These are the only methods the budget engine may call on GeneralLedger. Read-only methods are marked; writes target budget tables only.

Read-only queries against the ledger
python
def get_total_revenue_for_month(self, month: str) -> Decimal:
    """Sum of (Revenue credits − Revenue debits) across all transactions
    dated 'YYYY-MM'. Returns ZERO for months with no activity."""

def get_revenue_for_months(self, months: list[str]) -> Decimal:
    """Sum of get_total_revenue_for_month() across months. Convenience
    for the 3-month and 6-month smoothing paths."""

def get_category_actuals(self, linked_account: str, month: str) -> Decimal:
    """Sum of Expense debits to linked_account in a single month.
    Returns ZERO if the account is missing or has no activity in that
    month. Not cumulative — callers that need cumulative must iterate."""
Budget-table writes (isolated from the ledger)
python
def assign_to_envelope(self, month: str, category: str, amount: Decimal,
                       note: Optional[str] = None) -> Tuple[bool, str]: ...

def unassign_from_envelope(self, month: str, category: str, amount: Decimal,
                           note: Optional[str] = None) -> Tuple[bool, str]: ...

def move_budget_money(self, from_category: str, to_category: str,
                      amount: Decimal, month: str,
                      note: Optional[str] = None) -> Tuple[bool, str]:
    """Atomic. Inserts two rows sharing a related_id: 'move_out' on
    from_category and 'move_in' on to_category. Both amounts positive.
    Either both rows commit or neither does."""

def set_income_plan(self, month: str, expected: Decimal, source: str,
                    derived: Optional[Decimal]) -> Tuple[bool, str]:
    """Upsert. Sets created_at on insert, updated_at on every write."""

5. Budget Engine Logic
Put derivation and rollover math in a new budget_engine.py, not in ledger.py. The engine calls only the methods in §4.

Expected income derivation
python
def derive_expected_income(target_month: str, source_type: str) -> tuple[Decimal, str]:
    """
    Returns (amount, human_readable_label).

    source_type = 'last_month' -> get_total_revenue_for_month(prev_month)
    source_type = 'avg_3mo'    -> get_revenue_for_months(last 3) / 3
    source_type = 'avg_6mo'    -> get_revenue_for_months(last 6) / 6
    source_type = 'manual'     -> returns (ZERO, "Manual override") — the
                                  caller supplies the actual amount.

    First-run fallback: if every candidate month returns ZERO, return
    (ZERO, "No historical data available").

    Label examples:
      "based on Last Month actuals"
      "based on 3-Month average"
      "No historical data available"
    """
Envelope available
python
def envelope_available(category: str, as_of_month: str) -> Decimal:
    """
    Available = assigned − spent, adjusted by rollover_policy.

    assigned = cumulative sum of budget-ledger events for this category
               through as_of_month, per §3.
    spent    = ledger.get_category_actuals(envelope.linked_account, as_of_month)
               If linked_account is NULL, spent = ZERO.

    rollover_policy:
      'none'          -> only this month's net assignment counts. Prior
                         months are discarded, including overspend.
      'positive_only' -> cumulative positive assignment carries forward.
                         Overspend carries as a negative and is absorbed
                         in subsequent months.
      'full'          -> both positive and negative carry forward
                         without modification.
    """
Ready to Assign
python
def ready_to_assign(month: str) -> Decimal:
    received  = ledger.get_total_revenue_for_month(month)
    assigned  = sum(money(r['amount']) for r in ledger.get_budget_ledger_rows(month)
                    if r['event_type'] == 'assign')
    unassigned = sum(money(r['amount']) for r in ledger.get_budget_ledger_rows(month)
                     if r['event_type'] == 'unassign')
    # Moves excluded by design — see §3.
    return received - assigned + unassigned
6. Integration Points
update_account cascade. The existing method cascades account renames to sql_transaction_lines.account_name, sql_budgets.category, and sql_category_rules.category. Extend it to also cascade to sql_budget_envelopes.linked_account. Do not cascade to sql_budget_envelopes.category_name — envelopes are user-facing labels, not account references.

delete_account. Existing rule (no transactions = deletable) is preserved. On successful delete, if any envelope references the deleted account via linked_account, set that column to NULL and emit a notification via the existing NotificationCenter (Severity.WARNING, source "budget_engine").

Audit chain. After any budget operation, verify_audit_chain_integrity() must still pass. Budget writes must not appear in sql_transaction_history. This is a hard invariant; add a test if the project has a test suite.

Mode awareness. In Simple Mode, hide the Rollover Policy column in the UI and treat every envelope as positive_only at render time. The engine remains identical; only the presentation differs. Do not fork the engine on mode.

Rebuild the tab. Use a QSplitter(Qt.Orientation.Vertical) with three sections.

Top: ZBB header
QLineEdit for expected inflow (numeric; validated through money()).

QComboBox for smoothing: Last Month | 3-Month Avg | 6-Month Avg | Manual Override.

Contextual QLabel below the input:

Auto: Expected: $4,200 (based on Last Month actuals)

Manual: Expected: $5,000 (Manual Override) | Derived base: $4,200 | Delta: +$800

First run: Expected: $0.00 (No historical data available)

Read-only Income Received line (actuals for the month).

Ready to Assign line: green at exactly $0.00, amber when positive, red when negative.

Middle: envelope table
Column	Notes
Category	Foreground color from linked_account's account type via ui_helpers.ACCOUNT_COLORS. Envelopes with no linked account render in light gray.
Rollover Policy	Hidden in Simple Mode.
Assigned (This Month)	Per §3.
Activity (Actuals)	get_category_actuals for the month. Em dash when no linked account.
Available (Cumulative)	envelope_available.
Bottom: action buttons

Move Money — [From] → [To] : [Amount] : [Optional Note]. Calls ledger.move_budget_money.

Copy Last Month — for each envelope with a nonzero net assignment last month, pre-fill a draft assignment for the current month. Show a preview dialog; write only on confirm.

8. Edge Cases
No prior month data — derivation returns (ZERO, "No historical data available"); UI renders the first-run label; Ready to Assign renders $0.00 in green.

Envelope with no linked_account — Activity column shows —; Available = cumulative assignments only.

Linked account renamed — cascade updates linked_account; envelope's displayed name does not change.

Linked account deleted — allowed only per existing rule; linked_account becomes NULL; notification emitted.

Move to or from an inactive envelope — allowed. is_active is a UI filter, not a logical gate.

Copy Last Month with a category that no longer exists — skip and log. Never silently recreate an envelope.

Empty ledger — every calculation returns ZERO without raising.

9. Verification Checklist
Confirm each of these before declaring the work complete:

Post a transaction in the Transactions tab, return to Budgets; Ready to Assign updated without a manual refresh.

Switch smoothing from Last Month to Manual Override; both the amount and the contextual label text change.

Call move_budget_money; exactly two rows appear in sql_budget_ledger with a shared related_id; Ready to Assign is unchanged.

Set an envelope's rollover_policy to 'none'; at the month boundary, unspent funds reset to zero.

Envelope rows render distinct foreground colors matching ACCOUNT_COLORS for each linked account type.

First-run (empty ledger): every displayed monetary value is $0.00; no exceptions in the console.

Existing sql_budgets rows appear in the new UI; sql_budgets_deprecated exists and receives no further writes.

After any budget operation, verify_audit_chain_integrity() still passes.

Rename a linked account; the envelope's linked_account follows the new name and the envelope's displayed category name is unchanged.

get_budget_ledger_cumulative returns identical results whether called once or split across multiple calls.

Out of Scope
Changes to record_transaction, edit_transaction, void_transaction, or the audit hash chain.

Logging budget activity to the Audit Tab.

Scheduled or recurring budget transactions.

Mid-month income timing or proration.

Multi-currency budgeting (envelopes operate in the base currency only).

Cross-month reporting beyond "current month" and "cumulative through month."

Integration with merchant memory or tax templates.
